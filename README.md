# 通知中枢 notice-hub

把散落在**各个学校网站、校内邮箱、公众号**里的通知，汇总成一份**只有重点**的清单。
电脑桌面和手机主屏幕各一个入口。

```
采集 ──> 去重 ──> 关键词预筛 ──> 日期衰减/过期闸门 ──> LLM 精判抽取 ──> 分类 ──> 看板 + 推送
```

**它想解决的问题**：学校通知散在几十个单位网站上，格式各异、没有统一接口、还经常是 JS 动态加载的，
重要的东西极易错过。这个项目把「怎么把各种形态的网站抓下来」做成了一套可配置的系统。

### 几个做得比较扎实的地方

- **四种采集器**：RSS / IMAP 邮箱 / 网页（结构化 · 自动识别 · 变化检测）/ JSON API
- **网址自动探测**：在网页上输入任意网址，自动判断该怎么抓、生成配置、一键接入
- **选择器自动识别**：能认 class、`id` 前缀、以及「无 class 无 id 的孙节点」三种写法
- **时效性处理**：关键词判定叠加日期衰减与过期闸门，过期通知不会因为命中关键词就被当成重要
- **91 项离线自检**：`python tools/selftest.py`，不联网就能验证全链路

### 技术栈

纯 Python + 少量依赖（FastAPI / httpx / feedparser / BeautifulSoup / APScheduler），
存储用单文件 SQLite，前端是无构建步骤的原生 JS PWA。
**没有前端脚手架、没有数据库服务、没有 Docker**——双击一个 bat 就能跑。

### 实战记录

第二节记录了 **12 个真实学校网站**逐个实测的结果：哪几个能直接抓、哪几个是 JS 渲染、
正确的域名是什么（我猜错过好几个），以及两个就业网站「同一个 URL 换个请求方式就返回 JSON」
的突破口。这部分大概是这个仓库里最有参考价值的内容。

## 一、5 分钟跑起来

1. **双击 `scripts\start.bat`**
   第一次会自动建虚拟环境、装依赖（约 1 分钟），然后自动打开看板。
   地址：<http://127.0.0.1:8787>

2. **建桌面图标**
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\create-shortcut.ps1
   ```
   - 加 `-AutoStart` 参数可顺便设置开机自启
   - 如果提示"running scripts is disabled"，先执行 `Set-ExecutionPolicy -Scope Process Bypass`
   - 双击桌面上的「通知中枢」即可启动（静默运行，无黑窗口）

3. **信息源已经预置了一个**
   项目自带的 `config.yaml` 里已经配好**北大教务部通知公告页**（2026-09 实测可用），开箱就有真实数据。
   另外两个源（校内邮箱、公众号 RSS）需要你自己填，见下面第二节。

4. **看数据**
   回到看板，点右上角 `⟳` 立即抓取一次。

> 首次运行会生成 `config.yaml` 和 `data\noticehub.db`，都在项目目录里，删掉即可重置。

## 二、配置信息源

`config.yaml` 里有三类源，都是**把注释去掉、填上值**就能用。

### 1. 校内邮箱（最推荐，先配这个）

学校的正式通知几乎都会发邮件，这个源最可靠：

```yaml
sources:
  imap:
    - name: 校内邮箱
      enabled: true
      host: imap.pku.edu.cn        # 换成你学校邮箱的 IMAP 地址
      port: 993
      ssl: true
      username: 你的学号@pku.edu.cn
      password: 邮箱授权码          # 注意：多数邮箱要单独申请"授权码"，不是登录密码
      mailbox: INBOX
      since_days: 3
      weight: 1.5
```

程序**只读不删不改**（用 `BODY.PEEK` + 只读模式打开），不会动你的邮件。

### 2. 网页监控（已预置 12 个源，一般不用改）

`config.yaml` 里已经配好这些源，全部实测过：

| 源 | 模式 | 最新日期（2026-09 实测） |
|---|---|---|
| 教务部 · 选课与课程 / 四六级 / 推免 / 转专业 / 本科生科研 / 双专业辅修 | 结构化 | 2026-09-11 |
| 北大新闻网 · 信息预告（讲座） | 结构化 | **2026-09-18（当天）** |
| 医学部 · 通知公告 / 校园信息 | 结构化 | 2026-08-14 |
| 医学部 · 讲座信息 | 变化检测 | — |
| 北大体育教研部 | 变化检测 | — |
| 北大就业中心 | **已关闭**（JS 单页应用，抓不到） | — |

单源配置长这样：

```yaml
sources:
  web:
    - name: 教务部·选课与课程
      enabled: true
      url: http://www.dean.pku.edu.cn/web/notice.php?type=4
      item_selector: "div.notice_item"   # 每条通知的容器
      title_selector: "a"
      link_selector: "a"
      weight: 1.6
```

三种模式：

| 模式 | 配置 | 适用 |
|---|---|---|
| **结构化** | 填 `item_selector` | 页面结构固定时最可靠，能拿到真实标题、详情页链接和日期 |
| **自动识别** | 填 `auto_detect: true` | 不想研究 HTML 时用，程序自己找列表结构 |
| **变化检测** | 都不填 | 兜底方案；把页面文字拆成行，只挑新出现的行（没有日期） |

**日期是自动抽的**，支持 `2026-09-10`、`2026年9月10日`、`17 Nov 2025`、`14 Aug`（无年份）等格式。
无年份时按「发布日期不可能在未来」推断年份——算出来比今天晚就判为去年。

**加新网页**：先试 `auto_detect: true`，不行就手工填选择器。用这个工具能自动打印可用的选择器：

```powershell
.venv\Scripts\python.exe tools\detect_selector.py "https://某个页面"
```

**★ 两条防炸闸门**（重要，别被吓到）：
某个源第一次抓取时，页面上**已有的历史条目会被全部收进来存进看板，但标记为「历史·未推送」，绝不会推送**——
否则你第一次接教务页，会被十几条旧通知一次性炸掉。之后真正新发的才进入推送候选。
另外发布日期超过 `filter.max_age_days`（默认 30 天）的条目也会被同样处理。

变化检测模式同理——首轮只建立快照基线，不产生条目不推送。

**已知不可用的源**：`portal.pku.edu.cn` 是 JS 渲染的，抓下来是空壳（实测 0 行可用内容），别浪费时间去配它。

#### 讲座网是怎么攻下来的（值得记一笔）

`lecture.pku.edu.cn` 静态页面只有 1101 字节纯文本（全是筛选表单），**列表是 JS 渲染的**。
但它用的 Yii 框架有个特点：**同一个 URL 带上 XHR 头请求就返回 JSON**：

```
GET https://lecture.pku.edu.cn/index.php
    ?r=lecturepre/index&per-page=60&order=addtime+desc&search[status][eq]=1
Header: X-Requested-With: XMLHttpRequest
→ {"err":0,"data":[{"subject":"...","speaker":"...","place":"...",
                    "begintime":"2026-08-19 14:30:00","addtime":1786812171, ...}],
   "returnpage":{"total":"941",...}}
```

为此我给采集系统加了一个 **`sources.api`** 类型（配置化的 JSON 接口采集器），
任何返回 JSON 的站都能接，配置项见 `config.example.yaml`。

**踩过的坑，省得你再试**：
- 北医那两个栏目**必须带 `index.htm`**：`/tzgg/` 返回的是空壳（19KB 全是导航菜单），`/tzgg/index.htm` 才有内容
- `jwc.bjmu.edu.cn`、`tw.bjmu.edu.cn`、`xsh.bjmu.edu.cn`、`scc.bjmu.edu.cn` 这些子域名**根本不存在**
- 正确的名字是「**北医教育处**」（不是教务处）、「**bytw**」（不是 tw/youth）
- `portal.pku.edu.cn`（校内门户）是 JS 空壳
- 医学部「讲座信息」给的日期是**活动时间**（可能在未来），不是发布时间

#### 一个重要的机制改进

因为讲座类信息的特点是「**提前一个月发布、下周才开讲**」，单纯按发布日期判过期会把它们全隐藏。
所以我加了 `expire_field`（有效期字段）：**只要活动还没开始，即使发布日期很老也不算过期**。
这条规则对讲座、报名、活动类信息都适用。

#### 两个就业站是怎么攻下来的

两个站**都不是真正的 SPA**，而是「服务端渲染 HTML + 同域 JSON 接口」的混合模式。
关键突破口都是**同一个 URL 换个请求方式就返回 JSON**：

**① `scc.pku.edu.cn`（北大就业）** —— 完全零鉴权，裸请求就返回 JSON：

```
POST https://scc.pku.edu.cn/f/newsCenter/ajax_thisNewsAndSiblingCategoryList
     categoryId=13&pageNo=1&pageSize=50          → object.newsPage.list（通知公告，776 条）
POST https://scc.pku.edu.cn/f/recruitmentinfo/ajax_frontRecruitinfo
     pageNo=1&pageSize=50&positionType=1          → object.list（招聘，约 5552 条）
GET  https://scc.pku.edu.cn/f/recruitmentFair/ajax_frontRecruitfair
     pageNo=1&pageSize=50&fairType=1              → object.list（宣讲会）
```
坑：它的 `/f/xxx/show` 这类 HTML 详情页会 302 跳登录，**但对应的 `ajax_*` 接口是公开的**，所以只走接口。

**② `scdc.bjmu.edu.cn`（医学部就业）** —— 两个坑：

1. **必须带 `X-Requested-With: XMLHttpRequest`**，否则返回的是完整 HTML 页面而不是 JSON
   （和讲座网同一个套路。子代理报告说"不需要"，我实测是**需要**的）
2. **站点极慢**：单次请求 21~50 秒，超过 nginx 的 60s 上限会吐 504 → `timeout_seconds: 120`，
   抓取间隔放到 3~6 小时，别把人家站打挂

```
POST https://scdc.bjmu.edu.cn/portal/home/recruitment-list.html?menuId=30
Header: X-Requested-With: XMLHttpRequest
Body:   pageIndex=0&pageSize=30&currentPage=1
→ {"data":[...],"total":3585,...}
```
坑：返回头写 `text/html` 但 body 是 JSON（采集器已做容错解析）；
公告类栏目的字段是嵌套的 `{type,showName,value}`，日期要取 `createTime.value`。

**医学部就业的两个栏目都停在很早**：就业信息最新 2025-06-06，新闻公告最新 2022-09-30（基本是僵尸栏目）。
仍然接上了——这样「源状态」面板会如实显示它们停更，而不是让你以为漏抓了。

#### 加新网页的方法

先试 `auto_detect: true`，不行用工具自动找选择器：

```powershell
.venv\Scripts\python.exe tools\detect_selector.py "https://某个页面"
```

如果是 JS 渲染的站，用 `sources.api` 类型，照抄 `config.example.yaml` 里北大讲座网那段。

## 三、★ 添加一个新网站（不用改代码）

点右上角 `⋯` → **「➕ 添加网站」**，把网址粘进去，点「探测」。

### 它会自动判断三种情况

| 探测结果 | 含义 | 之后怎么做 |
|---|---|---|
| **RSS 订阅源** | 这是个标准 feed | 点「加入采集」即可 |
| **静态列表页** | 自动识别到了列表结构（`item_selector`） | 点「加入采集」即可 |
| **JS 动态加载页** | 静态 HTML 里没有列表 | 会给出**疑似接口**（可以用 `sources.api` 手工配）和页面上的**其他栏目**让你换一个页面再试 |

探测结果里会显示：识别到多少项、多少项带日期、抓到的样例标题。**先看样例标题对不对，再点加入。**

如果给的是首页（没有列表），它会列出页面上所有「通知 / 公告 / 新闻 / 讲座 / 招聘」入口，
点一个更接近列表页的再探测即可。

### 选择器识别支持三种写法

国内高校站的 HTML 写得很杂，识别器现在能处理：

1. **有 class** → `div.notice_item`
2. **无 class 但有 id** → `li[id^=line_u]`（`id="line_u11_0"` 这种）
3. **无 class 无 id 的孙节点** → `div.list30 li`（自动往上找最近的带 class 的祖先）

实测这 12 个源 **12/12 全部识别成功**，耗时 0.3 秒。

### 加进来的东西存在哪

存在 `data/custom_sources.yaml`，**不会动你手写的 `config.yaml`**（保留注释）。
界面上可以随时看到已添加的列表并删除。

加完会**立刻单独抓一次**，马上就能看到结果，不用等整轮跑完。

## 四、开启 LLM 精判（"只抓重点"的第二道漏斗）

不填也能用（只靠关键词），填了会准很多——它能读懂"活动回顾"和"补退选截止"的区别，并**抽出截止日期、面向对象、你要做什么**。

```yaml
llm:
  enabled: true
  base_url: https://api.deepseek.com
  api_key: ""            # 建议改用环境变量，见下
  model: deepseek-chat
  min_importance_for_llm: 4    # 只有 4 分以上才送 LLM —— 省钱的关键
  max_calls_per_run: 20
  concurrency: 3
```

**建议不要把 key 写进文件**，改用环境变量：

```powershell
setx NOTICE_HUB_LLM_KEY "sk-你的key"
```

可用的环境变量：`NOTICE_HUB_LLM_KEY`、`NOTICE_HUB_LLM_MODEL`、`NOTICE_HUB_LLM_BASE_URL`。
任何兼容 OpenAI `/chat/completions` 接口的服务都能用（DeepSeek、通义、Kimi、本地 Ollama 等）。

**费用**：一句提示，两道漏斗，只有 4 分以上的条目才调用。按每天 20 条算，成本在**几分钱到一两毛**之间。

## 五、分类体系：信息怎么分门别类

所有通知会被自动归入 **10 个类目 + 1 个兜底**，看板按类目分组显示，也能按类目筛选：

| 类目 | 图标 | 覆盖什么 |
|---|---|---|
| **教务学业** | 📚 | 选课、补退选、考试、成绩、学籍、培养方案、毕业、推免、转专业、四六级、辅修双学位 |
| **讲座讲坛** | 🎓 | 讲座、讲坛、沙龙、学术报告、论坛、研讨会 |

## 九、常见问题

**Q：为什么什么都没抓到？**
先看控制台日志。三类源都可能有网络/认证问题：邮箱多半是**没用授权码**；网页第一次只建基线不产出条目；公众号多半是那个号还没被 RSS 服务收录。

**Q：日期为什么显示成去年 / 未来？**
有些列表页（比如医学部）**不显示年份**，只有 `14 Aug`。程序按"发布日期不可能在未来"推断：只要算出来比今天晚，就判定为去年。
这是启发式规则，绝大多数情况对，但如果某个页面确实会提前发布（比如预告未来日期），可能推断错。改 `app/autodetect.py` 的 `_resolve_year` 可以调整。

**Q：看板上为什么有"历史·未推送"的条目？**
两种情况：① 某个源**首次接入**，页面上已有的历史条目会全部入库（可查）但不推送；② 发布日期超过 `filter.max_age_days`（默认 30 天）的旧通知。
这两种都只入库不推送，防止你第一次接一个源就被几十条旧通知炸掉。

**Q：分错类了怎么办？**
改 `app/categories.py` 里对应类目的 `keywords`。规则是"关键词越长权重越高"，所以给容易搞混的场景加更具体的关键词就能抢回来（比如"二次招生"比"宣讲会"权重高）。
改完不用重启，下一轮抓取生效。

**Q：推送太频繁 / 太少？**
- 太频繁：调高 `notify.min_importance`（5 = 只推最致命的），或调低 `notify.instant_push_max_per_day`
- 太少：检查 `filter.l3_keywords` 是否覆盖了你们学校的用词（比如"学籍异动""培养方案"这类你没想到的词），或者调低 `notify.min_importance`
- 想让它彻底不推只看看板：把 `notify.wechat.enabled` 改成 `false`

**Q：想调"什么算重点"？**
改 `config.yaml` 的 `filter` 段。`l3_keywords` 命中直接判 5 分，`l2_keywords` 判 4 分，`drop_keywords` 命中直接丢弃（除非同时命中 l3）。改完不用重启，下一轮抓取生效（配置在每次启动时读取）。

**Q：端口 8787 被占用？**
改 `config.yaml` 的 `server.port`，然后同步改桌面快捷方式（重跑 `create-shortcut.ps1`）。

**Q：数据存在哪？会上传吗？**
全部在本机 `data/noticehub.db`。除了你配置的采集源、LLM 接口和微信接口，程序不往外发任何东西。

**Q：怎么彻底卸载？**
删掉整个 `notice-hub` 文件夹，再删掉桌面和启动文件夹里的快捷方式。

## 十、看板怎么用 & 为什么有时候"看到的不多"

### 9.1 默认视图是「全部通知」

之前默认是「只看重点」（重要度≥4），加上日期衰减规则后**几乎什么都筛不出来**——这是设计失误，已改。
现在默认 **「全部通知」**，按重要度排序，你能看到所有当前有效的条目。

顶部四个筛选：全部通知 / 只看重点 / 未读 / 星标。
排序规则：**全部通知按重要度，点进具体类目按时间**（工具条上的 `⇅` 可手动覆盖）。

### 9.2 ★ 菜单里的「查看各源抓取状态」

**这是回答"某个网站到底有没有东西"的地方。** 点右上角 `⋯` → 查看各源抓取状态，会列出每个源：

| 状态 | 含义 |
|---|---|
| **活跃** | 有当前有效的内容 |
| **停更** | 抓到了，但最新一条是 60 天前的——**这个站自己很久没更新了**，不是程序的问题 |
| **全部过期** | 最新一条超出显示范围，点「过期通知：显示」能看到 |
| **监听中** | 变化检测模式，首轮只建基线，页面有新内容才产出 |
| **无数据** | 一条都没抓到，检查地址或看控制台日志 |

每个源还会显示：抓到几条、可见几条、最新一条的日期和距今多少天。

### 9.3 三道日期闸门

| 参数 | 默认 | 作用 |
|---|---|---|
| `filter.importance_decay_days` | 7 | 发布日期超过 N 天 → 重要度压到 2 分以下。4 月的「停电停水通知」不会再显示成 5 分 |
| `filter.visible_days` | **60** | 发布日期超过 N 天 → 标记过期，默认隐藏、永不推送 |
| `filter.upcoming_days` | 30 | 正文里提到未来 N 天内的日期 → **不算过期** |

**两道例外**（重要，否则讲座类会被误杀）：

1. **API 源给了 `expire_field`**（讲座用 `begintime`）→ 只要活动还没开始，发布日期再老也不算过期
2. **正文里提到未来日期**（"9月25日前完成"）→ 同样不算过期

`visible_days` 从 30 放宽到 60，是因为 30 天会让**本身就低频更新的站整站消失**
（团委最新 8-14、讲座网 8-16、体育 8-27，全在 30~35 天，一放宽就都回来了）。

### 9.4 改了配置不想清库？调「重算」

重要度和过期状态是**入库时算好存下来的**。所以改完 `config.yaml` 的关键词或日期阈值后：

- 重启服务会自动重算一次（启动时跑）
- 或手动调：`POST /api/recompute`

这样不用清库重抓。

### 9.5 关于「讲座同步到当日」的诚实说明

我做了能做的：**讲座类源每 5~10 分钟抓一次**（其他源 15~30 分钟）。

但天花板不在我这边：

1. **源页面自己的更新频率**。北大新闻网「信息预告」最新一条是 2026-09-15；**北大讲座网最新一场是 2026-08-26 开讲，之后停止更新**——不是我没抓到，是它没发新的。
2. **公众号那条路更慢**：Wechat2RSS 官方口径平均 6 小时，遇风控可能几天。

所以程序能保证的是「**源一更新我几分钟内就知道**」，不能保证「源每天都有更新」。
打开「各源抓取状态」就能看出哪些站是活的、哪些站自己停更了。

3. **官网镜像有滞后** —— 教务部通知页最新是 2026-09-10，新闻网信息预告是当天。官网通常比公众号慢，不是所有通知都会同步到官网。
4. **无年份日期的年份是推断的** —— 见常见问题，极端情况可能差一年。
5. **网页变化检测会误报** —— 页面改版、广告轮播都会产生"新行"。某个源噪音大就给它填 `item_selector` 走结构化模式。
6. **就业中心抓不了** —— scc.pku.edu.cn 是 JS 单页应用，需要它背后的接口地址。
